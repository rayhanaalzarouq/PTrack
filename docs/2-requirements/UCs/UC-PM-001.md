### 2. Brief Description
The user creates a new project in PTrack by providing its name and, optionally, a description, so it can be tracked going forward.
---
### 3. Preconditions
- The application is open and the user has access to the project list view.
- No login or account is required (single local user per NFR-006 and PRD assumptions).
- No specific configuration is required.
---
### 4. Trigger
The user selects the action to create a new project.
---
### 5. Main Success Scenario (Basic Flow)
| Step | Actor Action | System Response |
|------|--------------|----------------|
| 1 | User selects "Create Project" (or equivalent action) | System presents fields to enter the project name and an optional description |
| 2 | User enters a valid project name | System accepts the input |
| 3 | User confirms creation | System creates the project, records the creation date automatically, adds the project to the project list, and opens its details (see UC-PM-003) |
---
### 6. Alternate Flows / Exceptions
#### A1 - Description Entered
- Condition: The user also enters an optional description (maximum 250 characters).
- Flow:
  1. User enters a description; a counter below the field shows the characters used out of 250.
  2. System stores it alongside the project name.
#### A2 - User Cancels
- Condition: The user selects Cancel or the close icon on the create form.
- Flow:
  1. System closes the form without creating a project (see FR-PM-001 AC10).
#### E1 - Empty Name Submitted
- Condition: User attempts to confirm creation with an empty name field.
- System Response: System rejects the creation and indicates that a name is required (see FR-PM-001 AC2).
#### E2 - Creation Failure
- Condition: An unexpected error occurs while creating the project.
- System Response: System does not create a partial project and reports the failure to the user with a warning message (see FR-PM-001 AC3, FR-DATA-001 AC3).
#### E3 - Description Limit Reached
- Condition: User reaches 250 characters in the description, or pastes text longer than the limit.
- System Response: System stops accepting further characters when typing and cuts pasted text to 250 characters (see FR-PM-001 AC6).
#### E4 - Name Already Used
- Condition: A project with the same name already exists.
- System Response: System rejects the creation and displays a message that the name is already used (see FR-PM-001 AC8).
---
### 7. Postconditions
#### Success Postconditions
- A new project exists and appears in the project list with the entered name; its description (if any) and creation date are stored; its details are displayed.
#### Failure Postconditions
- No new project is created; the project list is unchanged.
---
### 8. Business Rules
- BR-001: A project name is required to create a project (per FR-PM-001).
- BR-002: The description is optional with a maximum of 250 characters, enforced by blocking input; the creation date is generated automatically by the system (ADR-007).
- BR-003: Project names are unique (ADR-010); two names are the same when they contain the same letters, ignoring letter case and spaces.
---
### 9. Non-Functional Requirements Impacted
- NFR IDs (from NFRs.md): NFR-001, NFR-002, NFR-006
- Impact notes per referenced NFR:
  - NFR-001: The creation flow should remain simple and require minimal user effort.
  - NFR-002: Project creation should complete within the 2 second response target.
  - NFR-006: No personal user information is collected as part of project creation.
